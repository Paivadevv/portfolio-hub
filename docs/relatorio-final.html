1. Introdução

Este relatório descreve o desenvolvimento do PortfolioHUB, um repositório no GitHub criado para reunir projetos acadêmicos e pessoais de forma organizada, documentada e versionada. O trabalho atende ao desafio da entrega intermediária do Bootcamp I, que propõe aplicar boas práticas de versionamento com Git, publicar uma página com o GitHub Pages e integrar o repositório ao LinkedIn.

2. Objetivos

  • Planejar e organizar um repositório com estrutura clara de pastas;
  • Criar um site de portfólio simples (HTML e CSS) e versioná-lo com Git, a partir da versão 1.0;
  • Documentar o repositório e cada projeto com arquivos README.md;
  • Publicar o site no GitHub Pages;
  • Tornar o repositório público e divulgá-lo no LinkedIn;
  • Apresentar o trabalho em um vídeo de cerca de 5 minutos no YouTube.

4. Etapa 1 — Planejamento do repositório

Antes de criar os arquivos, foram definidas as seções do repositório: site (raiz), projetos acadêmicos, projetos pessoais e documentação. A estrutura de diretórios ficou assim: 

portfolio-hub/
├── index.html                 → página principal do portfólio
├── css/style.css              → estilos do site
├── img/avatar.svg             → imagem de perfil
├── projetos/
│   ├── academicos/
│   │   ├── ironstack-banco-de-dados/       (README.md)
│   │   └── artigo-programacao-funcional/   (README.md)
│   └── pessoais/
│       ├── automacao-python/               (README.md)
│       └── estudos-java/                   (README.md, OlaMundo.java)
├── docs/
│   ├── relatorio-final.html   → este relatório
│   ├── guia-git/README.md     → comandos Git e exemplos de commits
│   ├── guia-publicacao.md     → GitHub Pages, repositório público e LinkedIn
│   └── roteiro-video.md       → roteiro da apresentação
├── .gitignore
└── README.md                  → documentação principal

O index.html fica na raiz para que o GitHub Pages publique o site sem configurações extras. Cada projeto tem sua própria pasta, o que facilita adicionar novos projetos no futuro.

5. Etapa 2 — Criação e versionamento do projeto

O projeto inicial é o site de portfólio, feito apenas com HTML e CSS, sem JavaScript ou frameworks. Ele possui as seções: Apresentação, Sobre mim, Projetos (acadêmicos e pessoais), Habilidades, Documentos e Contato, além de layout responsivo para celular.

O versionamento seguiu dois marcos, cada um com commits pequenos e descritivos:

VersãoConteúdoCommits
v1.0 Site inicial e README principal chore: adiciona .gitignore
style: adiciona estilos do site em CSS
feat: adiciona imagem de perfil
feat: cria página principal do portfólio em HTML
docs: adiciona README principal do repositório
v1.1 Alterações enviadas ao GitHub: projetos, documentação, relatório e links atualizados docs: adiciona projeto acadêmico IronStack (banco de dados)
docs: adiciona projeto acadêmico do artigo de programação funcional
docs: adiciona projeto pessoal de automação em Python
feat: adiciona projeto de estudos de Java com primeiro programa
docs: adiciona guia de Git com comandos e exemplos de commits
docs: adiciona guia de publicação e roteiro do vídeo
docs: adiciona relatório final do trabalho
fix: atualiza links do GitHub e do GitHub Pages

Os commits foram feitos pela interface web do GitHub (envio de arquivos com mensagem de commit), e cada versão foi marcada com uma tag por meio de uma release (v1.0 e v1.1). Os comandos Git equivalentes para fazer o mesmo pelo terminal estão documentados em docs/guia-git/README.md: 

git add .
git commit -m "feat: cria página principal do portfólio em HTML"
git tag -a v1.0 -m "Versão 1.0 - site inicial do portfólio"
git push origin main --tags

As mensagens de commit seguem o padrão Conventional Commits (feat, fix, docs, style, chore), com uma mudança lógica por commit.

7. Etapa 4 — GitHub Pages

O site foi publicado pelo GitHub Pages em Settings → Pages → Deploy from a branch → main / (root). A página reúne o site, os projetos e os documentos do trabalho (este relatório e o guia de Git), como pede o desafio. Endereço: https://paivadevv.github.io/portfolio-hub/

8. Etapa 5 — Compartilhamento e integração com o LinkedIn

O repositório foi configurado como público, recebeu descrição, link do site e tópicos (portfolio, html, css, github-pages, git) e foi fixado no perfil do GitHub. No LinkedIn, o projeto foi adicionado à seção Projetos, com descrição, habilidades (HTML, CSS, Git, GitHub) e os links do site e do repositório. As instruções detalhadas estão em docs/guia-publicacao.md.

9. Etapa 6 — Revisão final e apresentação

Como revisão final, foi preparada uma apresentação em vídeo de cerca de 5 minutos, publicada no YouTube, mostrando a estrutura do repositório, a documentação, o histórico de versões, o site no GitHub Pages e a integração com o LinkedIn.

12. Conclusão

O desafio permitiu praticar todo o ciclo de um projeto em repositório: planejar a estrutura, criar o conteúdo, versionar com Git em etapas, documentar com README, publicar com o GitHub Pages e divulgar no LinkedIn. O resultado é um portfólio simples, organizado e público, que poderá ser atualizado a cada novo projeto, bastando criar uma nova pasta em projetos/, documentá-la e registrar a mudança com um novo commit.
